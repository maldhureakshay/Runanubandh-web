# Mali Runanubandh — Flutter Web Admin

Admin UI for the same Firebase project as the Android app (`mali-runanubandh`).  
Served from Firebase Hosting at **`/admin/`** alongside the existing static landing page.

## Prerequisites

- Flutter SDK (stable) with Web enabled: `flutter config --enable-web`
- Firebase CLI: `npm i -g firebase-tools`
- Access to the Firebase project and a Web app registered in the console

## One-time Firebase Web setup

1. **Register a Web app** in [Firebase Console](https://console.firebase.google.com/) → Project settings → Your apps → Web.
2. Generate options (recommended):

   ```bash
   dart pub global activate flutterfire_cli
   flutterfire configure --project=mali-runanubandh --platforms=web --out=lib/firebase_options.dart
   ```

   This overwrites `lib/firebase_options.dart` with real `apiKey`, `appId`, `messagingSenderId`, etc.

3. **Enable Authentication** → Sign-in method → **Email/Password** (or add others later).

4. **Custom claims (admin)** — see below. Without `admin: true` on the ID token, users are redirected to **Unauthorized** after sign-in.

5. **Firestore** (optional for dashboard metrics): create document  
   `admin_dashboard/summary` with fields such as:

   ```json
   {
     "totalUsers": 0,
     "pendingProfiles": 0,
     "updatedAt": "<server timestamp>"
   }
   ```

   Add security rules so **only admins** can read/write this path (see Security section).

## Local development

```bash
cd admin
flutter pub get
flutter run -d chrome --web-port=8080
```

For subpath behavior closer to production:

```bash
flutter run -d chrome --web-port=8080 \
  --web-browser-flag "--disable-web-security"
```

Use **`flutter build web --base-href /admin/`** before checking asset URLs; locally the app often runs at `/` while production is `/admin/`.

## Build & stage for Firebase Hosting

From the **repository root** (parent of `admin/`):

```bash
./scripts/stage_admin_web.sh
```

This runs:

1. `flutter pub get`
2. `flutter build web --base-href /admin/ --release`
3. `cp -R admin/build/web/* admin/`

Firebase **`public`** is the repo root (`.`). Hosting serves:

- `/` → existing `index.html` (unchanged)
- `/admin/...` → Flutter artifacts under `admin/` (`index.html`, `main.dart.js`, `assets/`, …)

`firebase.json` **ignores** Dart sources under `admin/lib`, `admin/web`, `admin/pubspec.yaml`, etc., so only built files in `admin/` are uploaded from that folder.

## Deploy

```bash
firebase deploy --only hosting
```

## Custom claims: grant admin

ID tokens must include `admin: true`. Set with the **Admin SDK** (never from the client):

**Node (example)**

```js
const admin = require('firebase-admin');
admin.initializeApp();
admin.auth().setCustomUserClaims(uid, { admin: true });
```

**Cloud Shell / one-off**

Use a small Node script or Firebase **Extensions** / callable **HTTPS** function restricted to project owners.

After setting claims, the user must **sign out and sign in again** (or wait for token refresh). This app calls `getIdTokenResult(true)` on redirects to force refresh.

## Security best practices

| Topic | Recommendation |
|--------|------------------|
| **Claims** | Treat `admin` claim as coarse gate; enforce again in **Firestore rules**, **Storage rules**, and **Cloud Functions**. |
| **Rules** | Never rely on UI alone. Example idea: `allow read, write: if request.auth != null && request.auth.token.admin == true;` on admin-only collections. |
| **Least privilege** | Prefer per-area claims (`contentModerator`, etc.) as you grow. |
| **Audit** | Log sensitive actions in Cloud Logging / Firestore `audit_logs` via Functions. |
| **Secrets** | No service accounts or Admin SDK keys in this repo or in the Flutter web build. |

## Troubleshooting

- **Blank page at `/admin/`** — Run `./scripts/stage_admin_web.sh` so `admin/index.html` and bundles exist; confirm `firebase.json` rewrites and `ignore` rules.
- **`REPLACE_WITH_*` in firebase_options** — Run `flutterfire configure`.
- **Stuck on Unauthorized** — User lacks `admin` custom claim; set via Admin SDK and re-authenticate.
- **Firestore permission denied** — Adjust rules for `admin_dashboard/summary` (and any other collections) for `request.auth.token.admin`.
